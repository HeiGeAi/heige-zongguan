# 让 AI 不等你开口：定时任务和事件触发

**本章用到的几个词**：

- **PR**：合并请求。改完代码先提交上去等人审，审过才合进正式版本。
- **cron、launchd**：电脑自带的闹钟，到点自动运行一条命令。cron 是 Linux 和 Mac 都有的老办法，launchd 是 Mac 自己的，配置文件叫 plist。
- **webhook**：别的系统一出事，就主动给你发一条消息，不用你去问。
- **sidecar**：Antigravity 里跟着主程序一起跑的小后台任务，定时任务就是一种。

前面几章的起点都是你：你开口，总管才动。这一章把起点从你身上拿走。到点了、群里来了新意见、线上报错了，对应的成员自己被叫醒去处理，处理完只把要你拍板的事递到你面前。

## 先想清楚三件事

1. **什么信号叫醒它**：到点（每天 18 点、每周日早上）、来了新东西（新邮件、新反馈、新 PR）、出事了（报错、告警）。
2. **叫醒谁、怎么干**：派给哪个成员，在哪个目录，按哪份 skill 或 SOP 做，只读还是能改。
3. **什么时候找你**：只在要你拍板、或者没跑成的时候找你。平时一声不吭。

每个自动化任务配一份专属的 skill，把规矩、参考资料、脚本写在里面。要改这个任务怎么做，改 skill 就行，规则和脚本不用动。

## 规则写进团队表

在团队表里加「规则」行，用 `|` 分成八段：

```
规则 = 名字 | 成员 | 线名 | 指令 | 权限 | 并行 | 通知 | 工作目录
```

```
规则 = 意见处理 | codex | 意见 | 用 feedback-triage skill 处理这条新意见，能修的修好开 PR | 可写 | 3 | 需要时 | ~/code/my-app
规则 = 每日巡检 | kimi | 巡检 | 用 daily-check skill 看昨天的报错日志，写一份三行日报 | 只读 | 1 | 每次 | ~/code/my-app
规则 = 周日大扫除 | codex | 大扫除 | 用 weekly-cleanup skill 找出本周重复写了两遍的代码和没拆干净的旧功能，开一个清理 PR | 可写 | 1 | 需要时 | ~/code/my-app
```

| 段 | 写什么 | 默认 |
|---|---|---|
| 名字 | 触发时喊这个名字 | 必填 |
| 成员 | 团队表里的成员名 | 必填 |
| 线名 | 同一条线同时只跑「并行」那么多份，多出来的会被拒绝，下次再处理 | 规则名 |
| 指令 | 一两句话，说清按哪份 skill、做到哪一步 | 必填 |
| 权限 | 只读 / 可写 | 只读 |
| 并行 | 这条线最多同时几份 | 1 |
| 通知 | 需要时（要拍板或没跑成才找你）/ 每次 / 不通知 | 需要时 |
| 工作目录 | 成员在哪个目录干活 | 当前目录 |

指令里不能出现 `|`。

## 触发一条规则

```bash
bash <skill目录>/scripts/run-rule.sh 意见处理 -e "反馈系统 feedback.new #12：导出按钮点了没反应 https://example.com/feedback/12"
```

它会做这几件事：

1. 查团队表里的规则；项目团队表要先 `team.sh trust` 过才执行，因为没人在场。
2. **去重**：同一个事件 10 分钟内只处理一次（用 `-k` 指定去重键，用 `ZONGGUAN_DEDUP_SECONDS` 改窗口）。同一件事被推了好几遍、同事补了一句话又贴了一张图，不会叫醒好几个成员一起改。
3. 把指令、事件、决策记录的位置、什么时候找人，拼成一份简报，按规则的线名、并行数、权限派给成员。
4. 成员回复第一行写了「【要你拍板】」，或者没跑成，就通知你；规则写了「每次」就每次都通知。
5. 每一单都记进台账（`~/.zongguan/ledger.tsv`），`stats.sh 7` 看最近 7 天哪条线最忙、哪个成员最常失败。

`-n` 只打印要派的简报，不真派，调规则时先用它看一眼。

## 通知只走一个出口

所有规则找你，都先追加进 `~/.zongguan/inbox.md`，再发到你设的出口：

```bash
export ZONGGUAN_NOTIFY_CMD="/path/to/notify.sh"   # 这个脚本收到一个参数：一句话通知
```

没设的话，macOS 上会弹系统通知。想推到飞书、企业微信、钉钉，写一个小脚本调它们的机器人接口，填进 `ZONGGUAN_NOTIFY_CMD`。不要每条规则各推各的。

## 到点触发：用你手上现成的定时功能

| 工具 | 怎么配 |
|---|---|
| Claude Code 桌面版 | 新建定时任务，指令写：`运行 bash <skill目录>/scripts/run-rule.sh 每日巡检，把结论告诉我` |
| Codex App | 在自动化（定时任务）里建一条，工作目录选项目目录，指令同上 |
| Antigravity | 内置的定时 sidecar（`"builtin": "schedule"`）用 `agentapi new-conversation` 开对话，提示词写同样的指令；建好后要你自己在面板里启用 |
| macOS 系统定时（launchd）或 Linux 的 cron | 直接跑命令，不用开任何 AI 产品，见下面 |

cron 例子（每天 18:05）：

```
5 18 * * * /bin/bash /path/to/zongguan/scripts/run-rule.sh 每日巡检 >> ~/.zongguan/cron.log 2>&1
```

macOS 用 launchd 时，在 `~/Library/LaunchAgents/` 放一个 plist，`ProgramArguments` 写 `/bin/bash`、`run-rule.sh` 的完整路径和规则名，`StartCalendarInterval` 写时间，再 `launchctl load` 它。

定时触发跑命令时，`PATH` 往往比你平时终端里的短。成员命令找不到时，在 cron 或 plist 里把 `PATH` 写全。

## 来了新东西就触发：事件

报错、同事意见、新 PR 这类事，等定时任务第二天再看就晚了，得一发生就叫醒成员。做法是让那边的系统把消息推过来（webhook），再调 `run-rule.sh`。几个事件来源还行；来源一多，最好统一接进一个事件中台，见 [event-hub.md](event-hub.md)。

## 注意

- 自动化跑起来以后，删除、停服、花钱、对外发消息、改权限这几类事，规则里也不要写成让成员直接做。简报会要求成员遇到这些停下来交决策卡。
- 权限写「可写」的规则，最好让成员只开 PR、不直接合并，合并前过一遍只读审查（审查规矩见 SKILL.md）。
- 定时任务第一次跑，用 `-n` 看简报，再手动触发一次看结果，确认没问题再交给定时。
